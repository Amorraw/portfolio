S

Situation

A four-platform recommendation system (Web, Mobile, Smart TV, IoT) on an Nx + pnpm monorepo had every project's build targets left empty — targets: {} — so `nx build/serve/test/lint` couldn't run reliably anywhere.

T

Task

Fix the build-governance problem first: define a canonical, repeatable target set per project type before any further feature work.

A

Action

Mapped @nx/esbuild/@nx/node to Fastify services, @nx/vite to React apps, @nx/react-native to mobile, and @nx/js:tsc to shared libraries, centralizing defaults in nx.json.

R

Result

A validated build-standardization plan — confirmed via nx graph and nx run-many — that unblocks consistent build/serve/test/lint across a five-platform codebase.

Interview talking points

  • Recognizing that the feature wasn't blocked by missing code — it was blocked by missing build infrastructure — and fixing the foundation first.
  • Real Nx/monorepo experience, a tool increasingly common at mid-size and growing engineering orgs, beyond a single-app Vite/CRA setup.
  • Comfortable giving an honest, granular completion estimate per subsystem instead of one vague "in progress."
